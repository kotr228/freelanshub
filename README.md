# Freelanshub

Біржа фрілансу: замовники публікують замовлення, фрілансери беруть їх у роботу, спілкуються в чаті, обмінюються файлами, а оплата проходить лише після виконання.

Стек: **Next.js 16 (App Router, Server Actions)**, React 19, TypeScript, Tailwind CSS 4, MySQL/MariaDB (`mysql2`), сесії в підписаному cookie (`jose`), паролі — bcrypt (сумісно з хешами старої PHP-версії).

## Можливості

- Реєстрація та вхід для двох ролей: замовник і фрілансер.
- **Замовник:** публікує замовлення (тип, спеціальність, дедлайн, бюджет, файли) з розрахунком комісії; бачить вкладки «Активні / Вільні / На виконанні / Очікують оплату / Завершені»; скасовує вільне замовлення; сплачує виконане; архівує сплачене.
- **Фрілансер:** каталог вільних замовлень з фільтрами (пошук, спеціальність, тип, дедлайн, ціна, сортування); ставить запитання до того, як взятися; бере замовлення, відмовляється від нього або позначає виконаним; вказує картку для виплат.
- Чат у кожному замовленні (окремий діалог для кожного фрілансера) з вкладеннями, файли замовлення, сповіщення про ключові події.
- Налаштування профілю: ім'я, контакти, «про себе», аватар, пошта, **зміна пароля**, банківська картка.
- Щоденне автоочищення старих замовлень та їхніх файлів (`/api/cron/cleanup`).

Життєвий цикл замовлення (поле `job.status`): `S1` без виконавця — вільне → `S1` з виконавцем — в роботі → `S2` — виконане → `S3` — сплачене → `S4` — в архіві.

## Запуск

```bash
cp .env.example .env      # вкажіть доступ до БД і SESSION_SECRET
npm install
npm run db:init           # створює БД і таблиці (нова інсталяція)
npm run dev               # http://localhost:3000
```

Продакшн: `npm run build && npm run start`. Потрібен Node.js 20.9+.

### Перехід зі старої PHP-версії

1. Зробіть резервну копію бази.
2. Виконайте один раз `mysql -u USER -p DB_NAME < db/migrate-from-php.sql` — додає нові колонки (`job.created_at`, `chat.sender`, `files.uploaded_by`), таблицю `notifications` (переносить `notifications_c`), таблицю `cleanup` і переводить таблиці в `utf8mb4`.
3. Скопіюйте старі завантаження: вміст `clients/uploads/` і `freelancers/uploads/` → `storage/uploads/` (шляхи в БД мають вигляд `uploads/...`, тож вони знайдуться).
4. Існуючі паролі продовжують працювати.

### Автоочищення

Раз на добу викликайте:

```bash
curl -H "Authorization: Bearer $CRON_SECRET" https://your-host/api/cron/cleanup
```

Видаляє вільні замовлення, дедлайн яких минув понад 30 днів тому, і завершені замовлення, старші за рік, разом із файлами.

## Структура

```
db/                      схема та міграція зі старої версії
src/app/                 сторінки (App Router)
  (auth)/                вхід і реєстрація
  (app)/client           кабінет замовника
  (app)/freelancer       каталог і замовлення фрілансера
  (app)/orders/[id]      сторінка замовлення: дії, файли, чат
  (app)/settings         налаштування акаунта
  actions/               Server Actions (auth, orders, settings)
  api/                   чат, завантаження файлів, аватари, сповіщення, cron
src/lib/                 БД, сесії, запити, валідація, константи
src/components/          UI-компоненти
storage/                 завантажені файли (не в git, віддаються з перевіркою доступу)
```

## Безпека

- Усі запити до БД параметризовані; доступ до замовлень, файлів і чату перевіряється на сервері.
- Файли зберігаються поза `public/` і віддаються як `attachment`, тож завантажений HTML/SVG не виконається на сайті.
- Облікові дані БД — лише в змінних середовища.

> ⚠️ Пароль до бази даних був закомічений у старому PHP-коді й лишається в історії git. Змініть його на хостингу.

Оплата наразі імітується (`payOrder` у `src/app/actions/orders.ts` записує платіж і виплату); для реальних платежів туди треба підключити платіжного провайдера.
